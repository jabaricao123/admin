# ADR-003: IM 登录（企业微信 / 飞书 / 钉钉）接入形态

- 状态：已采纳
- 日期：2026-10-05
- 关联模块：`/system/services/auth`（身份认证）、`/org/users`（用户管理-账号绑定）

## 背景

系统当前仅支持 Supabase 邮箱+密码登录。需要为内部员工提供企业微信 / 飞书 / 钉钉三家中任一家的扫码（PC）与免登（移动端 H5）入口，且**任一时刻全局只启用一家**。这一约束来自管理员的运维偏好（避免多渠道配置分散），不是技术限制。

## 决策

### 1. 接入范围

| 项 | 决策 |
|---|---|
| 入口形态 | PC 扫码 + 移动端免登，两者都支持 |
| 启用约束 | 部署级单选：全局任一时刻仅启用一家，admin 在配置页切换 |
| 账号匹配 | 按 **IM userid 预绑定** 匹配；不按邮箱或手机号自动匹配 |
| 密码登录 | 与 IM 登录并存；admin 可配置是否保留密码入口 |

### 2. 绑定关系存储

`profiles` 表增加三列：`wecom_userid` / `feishu_userid` / `dingtalk_userid`（均 nullable，各加 UNIQUE 约束）。

- **多槽位而非单槽位**：切换厂商不清空旧绑定，回切时旧关系仍可用。
- 录入通道：① admin 在 `/org/users` 编辑抽屉手工填写；② 用户已登录后扫码自助绑定本人账号。
- 解绑：仅 admin；用户不可自助解绑。

### 3. 会话签发

IM 登录成功后，由后端通过 Supabase Auth admin API 为该用户签发标准 Supabase session，前端无感。**不引入第二套会话体系**，与密码登录共用同一 RLS / session / 登出链路。

### 4. 安全与防代扫

- 二维码走三家原生 OAuth，自带 state + 短时效 + App 内二次确认，不另加 IP/设备指纹。
- IM 凭据（appid / secret / agentid）复用现有 `app.encrypt_secret` 加密存 Postgres，读写均写审计日志。
- 扫码登录的成功/失败同样落 `audit_logins`（复用 ADR-002 通道，新增 `via=im` 维度）。

### 5. 切换厂商

切换 = 配置热更新 + 强制所有在线会话登出（调用 Supabase Auth admin 全局签出）。**不自动清空任何绑定**；清空绑定是 admin 在配置页的另一独立手动操作。

### 6. 部署硬前提

三家 OAuth 均要求公网可达的 HTTPS 回调地址与企业侧 IP/域名白名单。系统必须部署在公网（或经反向代理暴露固定域名），此约束写进 README 部署章节，不作为功能开关。

### 7. 实施顺序

**飞书先行，企业微信第二批，钉钉后续**：

| 批次 | 厂商 | 理由 |
|---|---|---|
| 1 | 飞书 | API 现代、文档清晰，最快跑通「配置 → 绑定 → 扫码 → 免登」全链路，验证抽象 |
| 2 | 企业微信 | 用户基数最大但限制最多（IP 白名单、可信域名），在飞书抽象之上检验接口是否经得起差异 |
| 3 | 钉钉 | 留待前两家稳定后接入 |

串行而非并行：让 tracer bullet 发挥验证作用，避免在抽象未稳定时双倍返工。

## 考虑过的备选

| 备选 | 否决原因 |
|---|---|
| 邮箱 / 手机号自动匹配 | 三家对员工邮箱/手机号的授权口径不一，匹配不到时的兜底语义模糊；预绑定关系显式可控 |
| 单槽位 userid 字段 | 切换厂商即丢历史绑定，回切成本高 |
| 自建 session 体系 | 重复发明 Supabase Auth 已有的会话 / RLS / 登出链路 |
| service_role 直签 session | 违反 ADR-001 全局禁令 |
| 三家并行首批交付 | 无法在早期验证厂商抽象，返工面大 |

## 影响

- `profiles` 新增三列 + UNIQUE；pgTAP 覆盖三家 userid 的唯一性与绑定/解绑权限边界。
- 新增 `im_auth_configs` 表（启用厂商 + 三家凭据加密存储），RLS 仅 admin 可读写，凭据字段走 `app.encrypt_secret`。
- 登录页 `/login` 增加「扫码登录」Tab；移动端 H5 入口检测 IM UA 自动走免登。
- 切换厂商 / 查看凭据 / 强制下线全部写 audit。
- 组织/部门从 IM 同步、系统代用户调 IM API 发消息**不在本次范围**，归 sync / message 模块独立立项。
- 多租户下「不同租户选不同 IM」在商业化前另开 ADR。
